iLocate Non-AD Multi-Tenant Admin Site Requirements
1. Purpose

The Non-AD Admin Site will allow hospital clients that do not use Entra ID / Active Directory to manage their iLocate users, roles, and site access through a secure web-based administration portal.

This site will support passwordless login using email OTP and MFA, with no stored user passwords.

2. Core Requirements
2.1 Multi-Tenant Support

The admin site must support multiple hospital clients in a secure multi-tenant model.

Requirements:

Each hospital client shall be treated as a separate tenant.
Admin users shall only access data for their assigned hospital site.
Users, roles, locations, zones, assets, and reports shall be filtered by site_id.
No hospital client shall be able to view or modify another hospital’s users or configuration.
All admin activity shall be logged by tenant, user, action, date, and IP address.
3. Authentication Requirements
3.1 Passwordless Login

The system shall not use passwords for Non-AD users.

Login flow:

User enters email address.
System validates that the email exists and is active.
System sends a one-time passcode to the user’s email.
User enters OTP.
User completes MFA verification.
User is granted access based on assigned role and site permissions.
3.2 OTP Requirements
OTP shall expire after a configurable time period, recommended 5–10 minutes.
OTP shall be single-use only.
OTP resend attempts shall be rate limited.
Failed OTP attempts shall be logged.
Repeated failed attempts shall temporarily lock the login attempt.
3.3 MFA Requirements
MFA shall be required after OTP verification.
MFA may support email, authenticator app, or SMS if enabled.
MFA status shall be stored per user.
Admins shall be able to reset MFA for a user when needed.

5. Role Management Requirements

The admin site shall allow management of user roles and access levels.

Recommended roles:

Hospital Admin
Nurse Manager
Nursing Staff
Biomed Admin
Facilities Admin
IT Admin
Read-Only Viewer

Role permissions should control access to:

User management
Role assignment
Site access management
Asset search
Dashboard access
Reports access
Zone/location configuration
System settings
Audit logs

Only authorized admin users shall be allowed to assign or change roles.

6. Site Access Management Requirements

The system shall allow admins to control which hospital sites, buildings, floors, departments, or zones a user can access.

Requirements:

Assign user to one or more sites.
Assign user to one or more zones or departments if needed.
Restrict dashboard and reporting data by assigned access.
Restrict asset search results based on user site access.
Allow hospital admins to update access when staff roles change.
7. Admin Dashboard Requirements

The admin dashboard shall provide a summary view of the hospital tenant’s user and access status.

Dashboard items:

Total active users
Total inactive users

Recent logins
Failed login attempts

Users by role
Users by department
Site access summary

9. Security Requirements
No passwords shall be stored.
OTP codes shall be securely generated.
OTP values shall be hashed or securely stored.
All traffic shall use HTTPS/TLS.
Admin sessions shall expire after inactivity.
Role-based access control shall be enforced on both frontend and backend.
API endpoints shall validate tenant and site access.
Sensitive actions shall require re-verification when appropriate.
Account enumeration should be avoided during login.
All failed access attempts shall be logged.

Account activated

Site access changed

13. Success Criteria

The Non-AD Admin Site will be considered successful when:

Hospital admins can securely create and manage users.
Users can log in without passwords using OTP and MFA.
Role-based permissions are enforced correctly.
Site access restrictions prevent cross-tenant data exposure.
All admin and security actions are logged.
Hospital clients can operate iLocate without needing Entra ID / Active Directory.
